# Website Template

Базовый starter template для быстрых и качественных коммерческих сайтов.

## Стек

- React
- TypeScript
- Vite
- Tailwind CSS
- ESLint

Не добавляй новые зависимости без реальной необходимости.

## Архитектура

- `src/components/` — переиспользуемые UI-компоненты.
- `src/sections/` — крупные секции страницы.
- `src/data/` — контент, отделённый от UI.
- `public/images/` — изображения сайта.
- `App.tsx` — собирает страницу из компонентов и секций.

Используй существующие компоненты повторно, если они подходят.

Не создавай абстракции или сложную архитектуру без необходимости.

## Работа над сайтом

Перед изменениями:

1. Изучи существующую структуру и код.
2. Пойми требования задачи.
3. Используй существующие компоненты, если это возможно.
4. Меняй только то, что действительно необходимо.

Каждый сайт может иметь полностью уникальную структуру и дизайн.

Можно:

- добавлять новые секции;
- удалять ненужные секции;
- менять порядок секций;
- переделывать существующие компоненты;
- полностью менять визуальный стиль.

Не считай текущий дизайн обязательным.

## Контент

Отделяй контент от UI, когда это упрощает дальнейшее редактирование.

Для нового клиента обязательно замени тестовые:

- название;
- тексты;
- услуги;
- отзывы;
- контакты;
- изображения;
- ссылки.

Не оставляй тестовый контент в финальном сайте.

## Изображения

Используй `public/images/`.

Не используй base64 для изображений.

Не добавляй внешние изображения без необходимости.

Проверяй существование файлов и используй правильный `alt`.

## Код

Предпочитай:

- простой и читаемый код;
- TypeScript без `any`;
- семантический HTML;
- Tailwind CSS;
- адаптивную верстку;
- доступные элементы интерфейса.

Не используй inline styles, если задачу можно решить Tailwind CSS.

Не устанавливай библиотеку ради функции, которую легко реализовать существующими средствами.

## Дизайн

Приоритет:

1. Понятная структура.
2. Хорошая типографика.
3. Визуальная иерархия.
4. Адаптивность.
5. Доступность.
6. Производительность.

Не перегружай сайт эффектами, анимациями и декоративными элементами без причины.

## Проверка

После существенных изменений обязательно запусти:
`npm run build`

Исправь ошибки до завершения задачи.

Проверяй desktop и mobile.

Главное правило

Не усложняй проект без причины.

Сначала используй существующую архитектуру и компоненты.

Если требования проекта действительно требуют другой структуры — измени её.

Цель: качественный, быстрый, адаптивный и легко поддерживаемый коммерческий сайт.
